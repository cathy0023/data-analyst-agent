## RFC Lifecycle

```
inbox → draft → approved → completed
         ↑         ↓
       (rfc-author) (mgv-rfc-approve)
                            ↓
                      rfc-driven-dev
                      (plan → execute → review → fix → archive → deliver)
```

## Usage

1. **Capture requirements**: Place raw requirement docs in `inbox/` (manually or via `/rfc-brainstorm`).
2. **Author RFC**: Run `/rfc-author docs/rfcs/inbox/<file>.md` to draft a formal RFC in `draft/`.
3. **Approve**: Use `/mgv-rfc-approve` to move approved RFCs to `approved/`.
4. **Deliver**: Use `/rfc-driven-dev` to plan → execute → review → fix → archive → deliver.

> Note: This project was initialized via `/rfc-init` on 2026-06-15. The `inbox/` directory already contained one brainstorm output before init — it was preserved in place (RFC lifecycle starts at inbox, so no migration was needed).
